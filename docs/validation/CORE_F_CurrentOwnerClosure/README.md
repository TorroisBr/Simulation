## Supported profile and admission boundary

The audited profile is the fixed Daily-v1 selected runtime, with exactly the Required/ExplicitlyEmpty declarations above and current registered census providers. `OWNER_WRITER_MATRIX.csv` and the 24-operation overlay describe evidence for named registered cases; neither is a complete facade or writer closure. The owner-family ledger now supplies the missing current type/member/source inventory, but syntax alone does not prove all rooted mutation paths.

Supported roots must be traced from runtime facade/bootstrap/advance entry, through nested admitted owner operations and exact provider-installed owner references, into owner mutation, revision update, commit notification or enclosing epoch publication, and then to capture, hydrate/stage and alias validation. Read/proposal/pure-derived roots may be cleared only after their callees and aliases are proven non-mutating. Public visibility or a matching method name does not establish admission.

Current positive source evidence includes the 24 registered operation cases; the current `PersonStore` membership/binding and `GenealogyStore` parentage provider routes; current `SettlementPopulationRuntime` aggregate plus operation receipt witnesses; current restore staging/hydration and owner-recapture validators referenced by the matrix. Other preserved P12 routes must be reviewed using their current owner files and current provider registration rather than assumed removed.

## Known rooted candidates and explicit exclusions

- Public raw owner/service properties on `SimulationRuntime` can expose mutable objects. P12 supported callers must remain behind the admitted facade and exact mutation protocol; direct aliases are outside the supported mutation contract. Inventory and consumer proof remains pending for the full public property set.
- `SimulationRuntime.TryRecordSpatialObservations` and `TryAcceptSpatialRoutePlan` are public P8-D exact-zero-family writes with no P12 wrapper, selected Daily writer, or P12 epoch notification in their direct bodies. The exact-zero classification means no admitted selected producer in this profile, not that the owner can never be populated in another profile.
- `TryRecordPoliticalKnowledge`, `TryRegisterPoliticalKnowledgeHolder`, and `TryRegisterPoliticalDecision` are public deferred P12-F writes with no registered P12 operation wrapper/notification and no selected Daily producer. Keep them outside this profile's admitted roots; record their public exposure as a candidate bypass if scope changes.
- P15/P16/P17 public writers use composition-specific guards and are conditional external-profile routes. `TryApplyNamedBirth` and `TryApplyPersonDeathWithConflictInjury` have P12 profile rejection evidence in the historical P12-B reachability audit. Preserve these exclusions as scoped guards, not global API claims.
- `TesteSimulacao.TryStartExpedition` is a public conditional candidate requiring active session and `ExpeditionSystem`; no explicit Daily-v1 profile exclusion was established in this pass. It remains a concrete unresolved trace, not a supported route assertion.
