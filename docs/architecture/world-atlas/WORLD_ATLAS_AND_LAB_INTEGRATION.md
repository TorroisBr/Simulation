# World Atlas and Lab observation contract

This is a local Lab artifact for a specifically supported profile and a bounded capability set. The first implementation should use versioned UTF-8 JSON files selected explicitly from the desktop file picker. Lab runs as a separate .NET process. Capture is synchronous with the existing session authority; mapping and I/O use detached immutable values afterward. Atlas opens two observations in one run to show a change. A local file workflow gives deterministic fixtures, a human inspectable artifact and no required daemon. Embedded execution would couple UI lifetime and owner-thread admission. IPC or streaming would add message ordering, backpressure, failure recovery and version/security work. Reconsider only when file-based refresh is a demonstrated usability constraint.

## Read ownership and admission

Core owns the meaning and scope of each reader; the Lab owns invocation, wire mapping and publication. Follow FR-B/FR-C's immutable capability pattern, typed statuses, bounded reader set and coherent read rule. The delivered Faction/Person lease validates those exact authorities and their revisions. It cannot cover geography, City or Market writers by registration alone. Existing runtime observations, owner revisions and selected continuation validation are useful evidence, not a wider reader. Core's current host candidate uses an internal application and a narrowly named friend process host. Follow the eventual promoted supported host entry; choose a dedicated official host capability if one still needs design. General IVT, reflection over stores and temporary export from a test fixture internals path are excluded.

The proposed Core-side entry is one operation logically equivalent to `TryCaptureDailyAtlasFactsV1(expectedActiveWorld, out immutableCut, out diagnostics)` at the approved host boundary. Exact signatures and implementation sites belong in the post-promotion technical design. Under the active session owner thread and existing application/runtime admission, require fully published healthy session and quiescent completed positive advance, exact current session identity, WorldId, profile, absolute day, completed core sequence and boundary provenance. Admit or establish conservation for every relevant writer, including City stock, City registration/name, geography/anchor binding and any nested authority operations in scope. Verify identity/stamps before and after copying immutable values under one admission; if any relevant writer can mutate during the read, a final equality check alone is insufficient. Coordinate with the existing owner-thread/advance/session protocol to exclude reentrancy, loads or replacement, pending authoritative writes and mixed captures; no new global lock or write authority. Reuse an existing completed-boundary proof only internally where exact applicability is established. No token, persistence DTO, identity witnesses, hydration fields, guard internals or process-local epochs leave Core. Proven owner revision may appear as a capability source stamp; version, scope and boundary remain required even for immutable genesis geography with no separate public revision.

Before releasing the coherent cut validate finite counts, source row identities, field scope and mandatory references. Failed/rejected/partial advance, unbound/mixed read scope, wrong thread, busy/faulted/stale session, or reader failure emits diagnostics and no authoritative observation. Lab doesn't turn a failure into an empty set. Unsupported capabilities may be honestly disclosed without invalidating a successful compatible observation; absence is asserted only by complete coverage within the named scope. Producer walks the capture on the admitted thread and releases it before serialization. Hash/version and atomic write checks concern file integrity and provenance, not cryptographic authentication of the author's state.

## Proposed file v1

Use `*.atlas-observation.json`, schema `simulation.lab.observation`, numeric version 1. One closed envelope, two profile keys `atlas.demo/v1` and `atlas.daily-map-stock/v1`. Demo has explicit `sourceKind=demo`, isolated synthetic world/run and permanent Demo badge. The real profile has `sourceKind=core` and a canonical WorldId validated by the producer and corresponding wire syntax. Files opened manually are recorded artifacts with declared producer metadata; no identity, freshness or authenticity claim from file extension alone. A host-generated smoke binds actual provenance to observed stdout/evidence and output hashes. No tool writes an observation back into Core.

| Envelope part | Meaning |
|---|---|
| `profile, sourceKind, worldId, runId, observationIndex, previousDigest` | One Lab run assigns opaque runId; index starts at 0 and increments only for successful publication. First previousDigest is null. Each following file contains SHA-256 of the exact predecessor file bytes. Use fresh run identity for a separate Lab launch or session replacement in v1, even for same WorldId; no implicit comparison across reload, WorldId or fork. Atlas selection is keyed by world and type. |
| `boundary` | Absolute day and completed core sequence from one successful positive Daily-v1 boundary. Both are nonnegative signed 64-bit values serialized as canonical decimal strings; real captures require a positive completed sequence. Compare using numeric order. V1 observes daily boundaries only. A later intraday revision needs its typed logical instant, phase and same-instant ordering. |
| `producer` | Producer ID/version, immutable source/build identity, scenario ID/revision, actual Core composition profile and effective input fingerprint. Nullable display labels are not identities. These fields provide traceable scope, not regeneration or continuation instructions. |
| `capabilities` | Named and versioned sections declaring scope, coverage and authoritative owner/source stamp if supported. Present data are complete within declared scope. An omitted field makes no claim. Identifiers, status and payload agree; unknown wire/profile versions or unexpected capability shapes fail. |

Initial semantic rows are deliberately small. Use the same section shapes in demo fixtures and the future Core producer.

- `geography/v1`, scope registered P8 geography of this selected world. Hex rows `hexId,q,r,terrainId,terrainRevision`, with coordinate pair and terrain fields all present for geographic records or all null for legacy unplaced records; Location rows `locationId,anchorHexId`. Every anchor resolves. Optional future maps do not need to exist. Use checked Int32 q/r and unique nonnull coordinate pairs in this profile.
- `cities/v1`, scope current selected world City roster. City rows `cityId,label,p8LocationId`. Use the actual City runtime identity and exact P8 binding only. Label is nullable. A nullable binding under a complete supported Cities read means no projected binding for this City at this boundary; it does not deny legacy City spatial facts. A nonnull binding must resolve in geography. Where the binding capability is unsupported, advertise that limitation and omit the association (same null wire value in v1 with the section's binding coverage field declared `unsupported`).
- `city-market-stock/v1`, explicit scope `{cityId,itemDefinitionId}` for one selected market item in one actual City. Use `CAMPO_VERDE/TRIGO` as the proposed fixture selection, resolved by immutable authored definition before capture, with the actual installed City runtime ID in the artifact. Reject inconsistent/ambiguous resolution. Row `{cityId,itemDefinitionId,quantity}` with nonnegative integral units and same key as scope. Complete with an empty array means the exact supported key has no row and differs from a present row with quantity zero. Never equate unobserved stock or other items to zero. Verify the chosen quantity changes on at least one supported advance before claiming the real milestone; choose another proven row in the same scope if the accumulated operations cancel its net change.
- Optional no-data markers can explicitly disclose unsupported vs intentionally omitted capabilities. V1 has no generic event payload. The real contract requires `geography/v1`, `cities/v1` and `city-market-stock/v1` complete for their declared scopes. A producer version may omit other capabilities entirely; Atlas states that the artifact provides no such claim. Coverage choices are `complete`, `unsupported` and `not-included`; only complete carries row assertions, including known-empty. By contract partial coverage is expressed by narrowing and naming an exact scope with complete data inside it.

For the demo-shell checkpoint freeze a small closed fixture shape using this envelope. Required scalar/string keys are case-sensitive with ordinal identity; strings bounded to 512 UTF-16 code units, source digests lowercase 64-hex, IDs and scope keys nonblank. Use strict UTF-8, a 4 MiB file cap, depth 24, 4,096 Hex and Location rows each, and 1,024 City rows. Unknown or duplicate properties/IDs, exceeded limits, no corresponding source section, wrong coordinate/value/status and dangling included references yield typed diagnostics. The demo writer/fixtures and future Lab writer emit fixed field and ordinal key order. File repeats are idempotent by exact bytes; predecessor digest is over raw bytes, so reserialization is a new artifact. Write a temp sibling, validate, flush and atomically rename to a unique final path on supported local storage; existing published observations are immutable. Validate before changing the active UI state. A malformed/unavailable observation leaves the last usable view visible as stale with a reason.

To show a change, require both validated files with matching sourceKind, profile, world/run, producer/build, effective inputs, section versions and named scope, before/after day and sequence increasing, adjacent indices and the exact predecessor digest. Compare stable keys and exact values. For a missing predecessor or gap, show both available recorded cards without an inferred transition. Demo and Core observations cannot be compared to each other. A revision change alone is a source stamp change, not an explanation; a data change with no supported causal record is always labelled observed difference.

## Relationship to existing exchange and persistence

WI-A supplies published WorldId discipline. FR-B/C supply the existing coherent Faction path on their delivered host scope. WX-D provides the narrow World+Faction adapter for World Exchange v2, whose contract belongs to Simulation-External. The External v2 format requires nine arrays with whole-world coverage statuses and cannot express a scoped single City stock row or a retained-history window as complete. Keep its schema, producer and Web Explorer independent. For a future public whole-world export, reuse or extend WX-D only under that contract and cross-repo conformance review. Do not conflate this local observation artifact with `*.world.json`, official export scope or a P12 continuation image. Atlas never opens a P12 slot as its data source. Lab need not save a world to observe a completed boundary.

First demo capture after official Core host delivery uses the exact admitted Daily-v1 fixture (or its approved successor), real start and at least two successful advances. Verify the selected geography is installed and observable, the scoped City stock value changes and evidence comes from the same active WorldId. Preserve pre-existing P8/City anchor admissions. The currently inspected fixture authors a Hex and a Location and has two legacy Cities with no factual P8 City binding. The first integrated acceptance therefore navigates Hex → Location and independently World → City, then the City change panel. True click-through Location → City is a conditional follow-on for an already-admitted scenario with a real binding, or for separately approved future capability work. No profile widening is implicit. The existing finite-source Lab remains valuable in its own scope and cannot be joined to the Daily world as though it ran inside it.
