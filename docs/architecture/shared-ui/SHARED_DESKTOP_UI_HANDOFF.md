## Small contract

Expose a `ViewportPoint(double X, double Y)`, an explicit Y direction (down or up), and an immutable `ViewportTransform` value with caller-provided local origin, viewport center in DIPs, pan in DIPs and positive scale in DIPs per local unit. Define exactly three operations: forward `TryProject`, inverse `TryUnproject` and `TryReanchor` at a caller-supplied new scale and a control-relative DIP anchor, returning the updated transform. Return false without publishing a transform or using a result if any part of the supplied state, input, or computed output is nonfinite, direction is invalid or scale is nonpositive. Evaluate the same inverse and pan equations when the requested and existing scales are equal. The existing apps recalculate pan when zoom is already clamped. Omit tolerance rounding and policy clamping from the shared library. Use no heap allocation per projection. Adapter inputs derive from existing state in the UI thread.

- Forward projection uses `center + pan + ((local - origin) × scale)` in X. Apply a positive signed offset in Y-down and a negative signed offset in Y-up. The inverse subtracts center and pan in that order, divides by scale, applies the same Y orientation and adds the origin. For reanchoring, inverse-map the anchor with the old scale, then subtract center and the new scaled offset from the anchor in that order. Use the existing component-wise arithmetic order with no fused, reordered or approximate operations in the adapters. Keep the oriented addition/subtraction grouping for the Dungeon Y expressions.
- Atlas supplies a zero local origin, with long-recentered projected coordinates and Y-down. Dungeon supplies the existing scene center and Y-up, with half-centimetres converted to doubles before projection. Neither app changes its view model, selection, UI scale, camera limits, fit/padding calculation or storage. Callers own viewport readiness and invalid-input policy. For a rejected recalculation keep the existing camera; retain existing no-viewport, empty and pre-scale-normalization behavior at the current app entry points. If a valid existing layout or geometry can reject on the new finite boundary, stop the migration and reconcile the adapter with that baseline before acceptance.
- Keep pan and wheel dispatch, focus and capture bookkeeping, scroll event handling and fit local. Apply Atlas visibility clamping after reanchoring, as today. Anchor invariance applies before that clamp. Keep fit limits distinct from wheel limits in Dungeon. A shared camera type does not justify replacing each application's gesture state machine.
