### 2. Split the restore-time session/formatter edge

The ten-file restore SCC contains `TesteSimulacao.cs`; `P12GDailyV1RestoreCoordinator.cs:1166` currently calls `TesteSimulacao.CreateNpcChronicleFormatter`. The formatter lives in the combined `NpcChronicle.cs` source and cannot move independently of its domain record dependencies. Plan its extraction only after that exact closure is fixed. Its constructor receives host-neutral display lookups for NPC, location, item, and action IDs; it must not receive `SimulationConfigData`, `MonoBehaviour`, `Application`, `Debug`, or Unity collections. Unity and the .NET composition adapters bind the same semantic lookups from their effective definitions and staged owners.

Keep `TesteSimulacao : MonoBehaviour`, Unity input/logging, the active-session publication lock, operation counters, and Unity-specific facade in the Unity assembly. Move only the session value/state behavior that has no Unity-bound members (including pure report state) to Core where it reduces concrete references; retain a Unity `SimulationActiveSession` facade for `SimulationConfigData`, logger, and environment references. Restore creates the Core formatter against detached staged owners, then installs it in the fresh composition before restored-boundary admission. No formatter may observe the old active world or publish during staging.

The constructor contract is fixed by the existing `NpcChronicleFormatter` behavior and `CreateNpcChronicleFormatter` lookup semantics: missing or ambiguous identity behavior and display-name ordering remain unchanged. Compare formatted outputs and callback results for the same selected fixture before/after the cut.

### 3. Keep host identity, storage root, and diagnostics at the host boundary

Use the promoted descriptor/byte-slot interfaces. Core owns v1/v2 field semantics, strict parsing, mismatch categories, and byte-slot algorithms. Unity owns `Application.persistentDataPath`, Unity descriptor identity capture, and the v1-only adapter. The .NET host owns its fixed .NET identity manifest and an explicit caller-provided storage root. A Core composition receives the already selected root and narrow diagnostic callbacks; it does not query `Application`, inspect assembly locations, invent Unity fields, or use `Debug.Log`.

Retain one shared atomic slot implementation and the existing v1 bytes. The v2 descriptor is the approved typed schema only. No JSON save format, second slot, cross-host load, old-slot conversion, or generic workflow serializer is introduced.

### 4. Preserve the causal frozen payload and Unity numeric behavior

`P18DCommercialSharingBoundaryProvider` is classified `SplitHostDomain` because its frozen payload and edge payload use `JsonUtility.ToJson`/`FromJson`. For every selected rule currently using `Mathf.Max`, `Min`, `Clamp`, `Clamp01`, `FloorToInt`, `RoundToInt`, `Approximately`, or `Pow`, route to one Core equivalent only after cataloging the exact call sites and argument domains. Build a Unity reference-vector set for negative and boundary values, ties, signed zero, NaN/infinity, reversed clamp bounds where reachable, and supported domain limits. The Core implementation must match Unity outcomes for admitted values, including error/rejection behavior at out-of-domain values. A float representation probe alone is insufficient. No profile widening or unsourced claim of bit parity is allowed.

### 5. Preserve the clock/runtime admission owner
