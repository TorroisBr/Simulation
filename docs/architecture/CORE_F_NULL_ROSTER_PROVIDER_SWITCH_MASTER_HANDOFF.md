## 3. Admission, observability and mutation boundary

The actual provider class is `CommercialKnowledgeSharingDailyBoundaryStepProvider`
in `Assets/_Project/Scripts/P18DCommercialSharingBoundaryProvider.cs`, source blob
`23b999e78d2ee7577a590f1a12e2f3392b0f1971` at Core64610d6c.

- `TryCreateSteps` validates each live NPC and its nonblank/unique runtime ID
  before adding the frozen activation. Ordinary production-generated rosters
  contain valid non-null rows. The local `activations` cache and frozen City
  reference bindings keep their present lifecycle; no new owner is introduced.
- Snapshot `TryPrepareStep` initializes `prepared=null` and
  `failure=TimelineFailure.ContinuationFailed`, then checks kind/version, decode,
  arrays, activation existence and exact original payload equality. A tampered
  sequence18 payload normally fails that equality guard before roster validation.
- If reached, `ValidateRosterEvidence` rejects null rows, blank/null runtime IDs
  and duplicate IDs, then checks participant-to-roster membership/Person binding.
  The default row fails its existing runtime-ID guard. Keep that order.
- These checks precede participant resolution, plan fingerprint creation and
  `owner.TryPreparePhaseSnapshot`. That owner retains a phase snapshot only in
  its later `TryCommitPhaseSnapshot`; recipient Knowledge changes require a
  separately prepared and committed recipient batch. The timeline invokes a
  commit only after a successful preparation.
- Edge execution retains snapshot-step ordinal checks, exact activation bytes,
  retained phase-snapshot fingerprint and sender/receiver identity/City bindings.
  The admitted path cannot establish a matching retained source snapshot from
  this invalid roster. Preserve all those checks; do not add a new shortcut.

The decoded object/fields are observable through the public closed codec API and
test inspection. They are temporary transport values with no world-authority
publication. The rejection attempt prepares no commit and makes no new phase
snapshot, Knowledge/receipt write, revision update, ID allocation or RNG draw. Keep
existing operation/epoch/fault handling intact. This per-attempt guarantee does
not promise rollback of earlier steps in a multi-step advance or a capture token
from a failed advance. Sequence18 is a decoder observation, not an oracle run of
`TryPrepareStep`; source order supplies that rejection proof and new integration
tests must exercise the actual provider boundary.
