## Closure objective

The Phase 20 v1 objective is to prove that a temporary shared activity can
coordinate independent actors while preserving each actor's identity,
Knowledge, decision authority, commitments, lifecycle, and domain-owned
effects. The Phase Brief explicitly permits a synthetic proof followed by a
separately scoped existing consumer; it does not require a generic loader,
persistent Group/Organization, or every future activity consumer.

## Closure limits

If approved, close Phase 20 only within the v1 objective and the promoted
P20-A, P20-B, and P20-C scopes. Preserve these limitations:

- Exactly two Persons is a P20-C proving fixture, not a universal participant
  or role limit.
- P20-B remains only the Daily-v1 empty-owner census/admission checkpoint;
  Daily-v1 rejects populated P20 travel state.
- No persistent Party/Group/Organization, arbitrary role engine, save/load,
  replay, or cross-phase continuation is included.
- P12-B remains incomplete, P12-A remains `WAIT_DEPENDENCY`, and P13 remains
  blocked. No capture eligibility, export, or hydration is claimed.
- P11 external command capture, the P19 Mod API/loader, and War, robbery, gang,
  or other gameplay remain outside Phase 20.
- A supported non-Unity joint-travel Lab demonstration remains a documented
  follow-up; canonical architecture classifies it as follow-up demonstration,
  with no retrospective gate on the P20-C domain promotion.
- Future activity consumers and broader extensibility work require their own
  bounded contracts and prerequisites.

No code or checkpoint scope changes are proposed by this closure candidate.
Approval is only for a formal Phase 20 State closure marker within the limits
above. Until that approval is given and the marker is promoted, Phase 20 remains
open.
