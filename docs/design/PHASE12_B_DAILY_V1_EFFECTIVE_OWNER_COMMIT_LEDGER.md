## Census arithmetic and evidence

## Genesis, conditional composition, and public-but-unused APIs

- **Pre-runtime genesis:** P9-B publishes one authored Hex, anchored Location and scale context into the runtime-cloned `SpatialAuthorityStore` before `SimulationRuntime` construction and before the sealed Daily census baseline. These are present Required P8-A rows, but their genesis commits are not post-baseline Daily mutation-epoch events.
- **Explicitly empty P8-B/C:** passage/barrier state, crossings, City/site bindings and Person positions have installed exact owners and zero witnesses. Their public mutators do not establish a selected Daily caller. P10-A/B and P14-A/B profiles are rejected by Daily-v1; P8-E position commits are not called by the accepted Daily-v1 production composition. This is a current call-graph classification, not an API security boundary.
- **P8-D:** route observations and Person route-plan history are bound to exact stores at exact zero. Current selected Daily-v1 contains no producer callsite. Their presence does not imply P8-D gameplay.
- **P12-E military/factual authorities:** all eight sections are Required and bound to exact constructed stores, but zero at this profile. Normal P16/P17 writers belong to separate compositions. Do not infer a Daily shared-epoch edge from owner registration alone.
- **Public supported facade vs automatic daily loop:** institution, faction, claim, support, property and estate facades are registered supported runtime ingress even where the automatic daily actor loop does not invoke them. Their focused tests cover committed and rejected facade paths. Do not remove them from the matrix because they are not automatic-day actions.
- **ActorChoice/P11:** the P11 input census is included, but this selected bootstrap composes no external WorldCommand ingress; SampleScene begins with legacy NPCs without PersonId and an empty PersonStore. A future Person-backed input path is not evidence of a current Daily successful writer. P18 temporal actor-choice sections are not admitted here.
- **Standalone APIs/configurations:** an unscoped domain API or separate P10/P14/P16/P17 proving profile is not an admitted Daily-v1 ingress just because the same implementation type is public. If a future Daily composition exposes it, profile admission and this ledger must be revalidated.

## What this evidence does not establish

The current source and retained tests support the row patterns, exact installed-owner checks, baseline count, roster/cardinality transitions exercised, and the listed successful operation paths. This ledger does **not** prove:

1. that every effective census row has been exercised through every reachable runtime state or every supported public ingress;
2. that registered IDs exhaust every ingress or that all possible writers are wrapped by those operation scopes;
3. complete shared-epoch invalidation for all effective owners;
4. runtime-wide owner-thread/quiescence across the full effective owner/write surface;
5. a completed-boundary token tied to a successful advance sequence (an idle `CurrentDay` read is insufficient);
6. capture eligibility, export, staged hydration, P12-A readiness, P13 readiness, or Phase 12 closure.

One explicit census-surface reconciliation remains visible: `RuntimeIdAllocatorCensusProvider` can create fourteen per-kind counter witnesses, while `SimulationRuntime.InitializeNpcRosterCensusProtocol` registers only Events, Decisions, and (when `TravelPartySystem` exists) TravelParties. Startup source shows NPC/City/Location/Route allocations and scheduled-directive ID creation before the runtime census baseline; ExplorableSite/LocalTopology/Expedition/Organization/NotableItem allocation callsites are separate or conditional consumers. This explains several out-of-baseline/out-of-profile paths, but this ledger does not certify all eleven unregistered counter kinds as safely irrelevant to future continuation. Preserve them as an explicit owner-coverage/reconstruction question; do not claim a post-baseline successful writer or add counter sections without a reviewed scope decision.
