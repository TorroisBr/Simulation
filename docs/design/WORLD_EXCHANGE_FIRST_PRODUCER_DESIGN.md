## Placement and contract

The intended producer is a small **dedicated integration project in the Simulation repository**, outside `Assets/_Project/Scripts` domain authority, with a headless C# entry over the approved Simulation factual read host. It owns only mapping, wire DTOs local to the adapter, schema-version compatibility checks, UTF-8 JSON output, and an External contract conformance fixture. It does not grant `Simulation-External` access to live Stores and does not make Simulation domain code depend on TypeScript. A pure External TypeScript adapter would need an approved transport/interop boundary that does not yet exist; embedding export logic in `SimulationRuntime` would make the domain depend on the external document. Future consumers can reuse FR-B/FR-C without adopting World Exchange.

The adapter accepts a published `WorldId` from WI-A and a successful FR-C coherent capture from FR-B at one boundary. It rejects mismatched continuation/boundary provenance, best-effort/unavailable/unsupported Faction result, duplicate or invalid mapped IDs, failed schema validation, and any partial write. It maps World identity to `world.id` by its canonical text. It maps Faction IDs to stable type-scoped public strings using `sim:faction:` plus unpadded base64url of UTF-8 `FactionId.Value`; this reversible encoding is independent of names and insertion order, and must be versioned as adapter contract v1. It includes a faction `name` only when the source-owned display value is nonblank. It omits ideology, description, city/organization links and presentation tags. It does **not** publish `memberIds` until an approved Person factual cohort, matching ID mapping, and complete reference closure exist; the FR-C affiliation facts remain available for a later adapter slice. No actor Knowledge, `FactionStore` object, Unity type, P12 snapshot, or continuation data goes into public metadata.

The output is an immutable, versioned World Exchange document, validated by the External-owned `world-schema` contract and atomically written to `*.world.json` through temporary-file publication after validation. The artifact is a potentially stale read projection and does not carry save/continuation authority. JSON property order is canonical for stable fixtures; collections use FR-C deterministic order. Failed capture, mapping, validation, or file publication leaves no new final artifact.

## Current blocking contract pressure

World Exchange v1 requires `world` and **all nine collection arrays**. It has no coverage/capability marker. An empty array means no rows in the document but cannot distinguish authoritative known-empty from unsupported or omitted source coverage. The External pressure review explicitly forbids interpreting unsupported empty collections as factual absence and lists coverage semantics as a producer prerequisite. A `World + Factions` file padded with empty `people`, `cities`, `locations`, `organizations`, `institutions`, `items`, `historicalEvents`, and `relationships` would pass shape validation yet mislead consumers. Omitting arrays fails v1 validation. Therefore the first **legitimate** real artifact cannot be declared ready under the current contract.

Simulation-External must approve a backward-compatible explicit per-collection coverage declaration or a new schema version, plus validation and consumer semantics, that distinguishes `complete`, `partial`, and `unsupported` for every required collection. The first slice requires `factions=complete` for current Faction records and other unsupported collections explicitly marked `unsupported`; an actually proven empty source uses `complete` with `[]`. The coverage declaration must be part of the portable document, not an unbound sidecar. Simulation does not choose its wire field, version, or consumer display policy. Once approved, refresh this design against the exact External contract and confirm whether the first slice can be emitted without Person membership links. Do not silently reinterpret v1 arrays inside Simulation.

## Dependency and validation contract

WI-A and FR-C (hence FR-B) are **HARD_DEPENDENCY** for implementation. The External-owned coverage contract is a **HARD_DEPENDENCY** for artifact validity. P12-A/B/C and full P12, P13 mechanics, and P19 are **NO DEPENDENCY** for a live first producer; P12 infrastructure is **OPTIONAL_REUSE** only if later proven complete for projected owners. P13 is **ARCHITECTURAL_ALIGNMENT** for later fork export: the forked WorldId must differ and provenance must not be faked into v1 fields. P9 and P18 enter through their upstream contracts. This adapter must not read saves or implement transport, import, sync, REST, IPC, server, mods, or history export.

Likely implementation files after gates: dedicated `Tools/WorldExchangeProducer/` C# project/assembly, contract fixture and conformance tests; a narrow read-only host invocation for headless use. No P12-B runtime hotspot write should be needed in WX-D. A subsequent technical review must pin the External contract commit/version and exact conformance invocation before WX-D can be `READY_FOR_IMPLEMENTATION`.

Required later tests: canonical World/Faction ID stability across repeat export and save continuation; distinct fork identity once P13 exists; valid schema and coverage markers; no dangling references; unsupported versus known-empty; no fabricated names/members; deterministic bytes across insertion order/culture; changed read during capture fails; best-effort capture rejected; no file on failed validation/write; `world-io` accepts the produced portable artifact. Tests use a real Simulation factual fixture rather than External's mock projection source.

**Completion:** a schema-valid portable `.world.json` with honest collection coverage, sourced only from approved facts at one coherent boundary. It is currently blocked by the External contract decision and upstream implementation.
