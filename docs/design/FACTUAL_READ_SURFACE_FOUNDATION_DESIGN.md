# Factual Read Surface Foundation — bounded technical design (FR-B)

**Candidate status:** DESIGN PROPOSED; independent review required.

**Architecture base:** `f27954af6d880df123736027fd55e86874d6de68`.
**Owner:** Simulation read infrastructure, independent of World Exchange and WorldId allocation.

## Contract and scope

Add a Simulation-owned factual read namespace/file family (`Assets/_Project/Scripts/FactualRead/`) with small capability-specific reader contracts, copied immutable records, and one bounded read coordinator. No public Store, Unity component, persistence DTO, consumer DTO, or whole-world export object is returned. The foundation delivers the result/status vocabulary and synchronous capture protocol; FR-C provides the first real domain reader. The **only first coherent host profile** is the existing explicit `UnityBootstrapDailyV1` runtime admission profile, whether composed in Unity or a headless test host with an injected owner thread. A P18-backed profile, unselected/legacy runtime, arbitrary headless thread, or incomplete bootstrap returns `Unavailable` for coherent capture until a separately reviewed admission contract covers it. No cross-thread dispatcher is added.

`FactReadResult<T>` is a sealed immutable result whose `Status` is exactly `Present`, `Absent`, `Unavailable`, `Unsupported`, or `OutsideFactualScope`. `Present` carries a nonnull immutable value; `Absent` applies only to a queried optional scalar or keyed lookup and proves the authoritative owner has no such fact. A collection is `Present` with an immutable copied list, including `Present([])` when the entire authoritative collection is known empty; collection `Absent` is invalid. `Unavailable` means the owner/capture could not safely answer now; `Unsupported` means this capability/field is not supplied by the current reader; `OutsideFactualScope` identifies a requested derived/display-only value or actor-specific Knowledge, with reason `DerivedDisplay` or `ActorKnowledge` and an identified source/authority. Only `Present` and `Absent` claim World Truth. Per-field status can be used where a record has optional facts. Do not coerce unavailable/unsupported/excluded to empty/null or a fabricated label.

Readers expose their own domain record types and a stable capability ID/version. The coordinator accepts an explicit finite set of registered readers, not a generic reflective Store enumerator. It returns one immutable `FactualReadCapture` containing requested capability results, capture mode, logical boundary, and source-version evidence. `IFactualReader<T>` remains internal to Simulation implementations; consumers obtain registered read capabilities through a read-only host API. Version additions are explicit; changing a field's meaning requires a reviewed version change.

## Coherent boundary

`TryCaptureCoherent` begins only after successful world publication, on the exact `UnityBootstrapDailyV1` admission owner thread, outside bootstrap/day advance and with a healthy runtime. Bind one private `FactualReadAdmission` to that thread and to the exact composed `FactionStore` and `PersonStore`. Its non-reentrant `TryBeginRead` checks publication, profile, owner-thread identity, the runtime's active advance/bootstrap scope, and its own active state; it holds the read state through synchronous materialization and releases in `finally`. The same admission object is checked at **every mutation entry** of those two bound Stores: `FactionStore.TryRegister`, `TryRegisterAffiliation`, `TryApplyAdd`, `TryApplyEnd`; `PersonStore.TryRegister`, `TryRollbackRegistration`, `TryBindMaterializedNpc`, `TryRollbackMaterializedNpcBinding`. These are the mutating entries in the inspected canonical Store files. A wrong-thread or read-overlapping write rejects before touching records/revision; internal rollback is no exception. The admission binding is one-time after Store composition, preserves existing public signatures and mutation-guard semantics, and cannot silently fall back to an unbound Store for a runtime claiming coherent reads. Direct public Store references therefore cannot bypass admission. Reentrant same-thread writes during a read also reject. P12's selected profile already confines daily clock advancement to the owner thread and its admitted full-day operation; `TryBeginRead` additionally checks that operation is idle. The existing advance lease remains reentrancy protection, not a thread lock. No global P12 epoch is claimed.

The coordinator reads the completed logical day and both registered owner revisions before materialization, copies requested records without invoking user callbacks, reads day/revisions again, and releases admission in `finally`. Any mismatch, thrown reader, missing revision witness, reentrancy, or loss of owner-thread admission discards **all** copied output and reports `Unavailable`; no partial coherent result escapes. This is a bounded coherent cut for Faction/Person endpoint existence on the selected daily profile, not a whole-world snapshot. The selected profile's off-thread runtime advances are already rejected; the new Store admission closes the direct Faction/Person writer bypass specifically. Adding another factual reader requires listing and enforcing every owner/writer it reads before it may join this coherent profile. P18 intraday capture requires a later explicit timeline admission design.

The first capture spans only registered owner revisions. For FR-C these are `FactionStore.Revision`, `PersonStore.Revision` for verified affiliation endpoints, and the runtime logical clock/boundary. No claim is made about unregistered owners or a whole-world snapshot. A caller needing a capability outside this set receives `Unsupported`, never a silently broadened coherent claim. `TryCaptureBestEffort` may copy an individual capability without the full boundary check, but its result is permanently labelled `BestEffort` and cannot feed an authoritative exporter. The first implementation may omit best-effort entirely; it cannot silently fall back to it.

P12-B has **NO HARD DEPENDENCY**. Its partial epoch/quiescence protocol is **OPTIONAL_REUSE** only when its selected profile and complete projected owner set are proven; its current partial census is insufficient for FR-C coherence. P12-C/P12-A require **ARCHITECTURAL_ALIGNMENT** if they later reuse the same identity/read seams; no persistence DTO becomes a factual API. WI-A is **NO DEPENDENCY** for this generic foundation: capture identifies the runtime/boundary, and an identity-bearing export later combines the completed FR-C capture with the separately published WorldId. P18 is **ARCHITECTURAL_ALIGNMENT** for completed logical boundaries, not a redesign. P19 is **NO DEPENDENCY**.

## Implementation surface and validation

Expected files: new `FactualRead/*` contracts/coordinator and `.meta` files; a narrow `SimulationRuntime` admission/read facade and boundary witness; admission checks in the listed mutating entries of `FactionStore.cs` and `Person/PersonStore.cs`; focused EditMode tests. The Store changes only enforce this selected read boundary; they do not make Stores a consumer API or alter P12-B census. Audit any additional mutating entry in these exact Stores and add the same check before implementation review; no implementer may omit a discovered bypass while still labelling the result coherent. P12-B owns overlapping runtime bootstrap/day code, so this admission patch must be integrated serially against its current tip.

Tests: present versus authoritative absent, unsupported capability, unavailable during bootstrap/advance/fault/wrong thread/P18/unselected profile, explicit outside-scope classification with source for display/Knowledge requests, known-empty `Present([])`, no mutable alias escaping, stable deterministic capture order, before/after revision or boundary change fails atomically, exception fails atomically, reentrant capture fails, best-effort cannot pass the coherent-export gate, direct `FactionStore` and `PersonStore` off-thread writes reject without revision change, same-thread write attempted during capture rejects, accepted selected-profile writes remain valid, and a headless fixture with explicit selected profile/owner thread captures without Unity UI. No P12-A/P12-B/full P12 completion or P19 is required.

**Completion:** a bounded, capability-oriented factual read protocol with honest status and coherency labels, without a giant export DTO or a false global snapshot claim.
