# Factual Read Surface Foundation — bounded technical design (FR-B)

**Candidate status:** DESIGN PROPOSED; independent review required.

**Architecture base:** `f27954af6d880df123736027fd55e86874d6de68`.
**Owner:** Simulation read infrastructure, independent of World Exchange and WorldId allocation.

## Contract and scope

Add a Simulation-owned factual read namespace/file family (`Assets/_Project/Scripts/FactualRead/`) with small capability-specific reader contracts, copied immutable records, and one bounded read coordinator. No public Store, Unity component, persistence DTO, consumer DTO, or whole-world export object is returned. The foundation delivers the result/status vocabulary and synchronous capture protocol; FR-C provides the first real domain reader. The initial supported profile is a published, healthy runtime at a completed logical boundary under its serialized owner-thread execution contract. Headless hosts may use the same contract by serializing their runtime operations on a designated owner thread; this checkpoint does not add a cross-thread dispatcher.

`FactReadResult<T>` is a sealed immutable result whose `Status` is exactly `Present`, `Absent`, `Unavailable`, `Unsupported`, or `OutsideFactualScope`. `Present` carries a nonnull immutable value; `Absent` proves an authoritative owner was queried and there is no matching fact (or an authoritative collection is known empty); `Unavailable` means the owner/capture could not safely answer now; `Unsupported` means this capability/field is not supplied by the current reader; `OutsideFactualScope` identifies a requested derived/display-only value or actor-specific Knowledge, with reason `DerivedDisplay` or `ActorKnowledge`. Only `Present` and `Absent` claim World Truth. Collection results use the same status and a copied read-only list; an empty list is legal only with `Present` as a complete known-empty collection. Per-field status can be used where a record has optional facts. Do not coerce unavailable/unsupported/excluded to empty/null or a fabricated label.

Readers expose their own domain record types and a stable capability ID/version. The coordinator accepts an explicit finite set of registered readers, not a generic reflective Store enumerator. It returns one immutable `FactualReadCapture` containing requested capability results, capture mode, logical boundary, and source-version evidence. `IFactualReader<T>` remains internal to Simulation implementations; consumers obtain registered read capabilities through a read-only host API. Version additions are explicit; changing a field's meaning requires a reviewed version change.

## Coherent boundary

`TryCaptureCoherent` begins only after successful world publication, on the designated runtime owner thread, outside genesis, advance, activity transition, or any other in-progress admitted operation. It rejects a faulted runtime and an active read/advance lease. The coordinator holds a non-reentrant read admission for the entire synchronous capture, reads the logical boundary and each registered owner revision before materialization, copies all requested records without invoking user callbacks, reads boundary/revisions again, then releases in `finally`. Any mismatch, thrown reader, missing revision witness, reentrancy, or loss of owner-thread admission discards **all** copied output and reports `Unavailable`; no partial coherent result escapes. The host contract forbids concurrent direct owner mutations during the owner-thread window; an off-thread or unadmitted direct Store writer violates the supported profile and must not be represented as coherent. The later implementation must reject known bypass paths and demonstrate that the selected host serializes its writers. The existing advance lease is only reentrancy protection and cannot be called a thread lock. The partial P12 census epoch is not used as a global proof.

The first capture spans only registered owner revisions. For FR-C these are `FactionStore.Revision`, `PersonStore.Revision` for verified affiliation endpoints, and the runtime logical clock/boundary. No claim is made about unregistered owners or a whole-world snapshot. A caller needing a capability outside this set receives `Unsupported`, never a silently broadened coherent claim. `TryCaptureBestEffort` may copy an individual capability without the full boundary check, but its result is permanently labelled `BestEffort` and cannot feed an authoritative exporter. The first implementation may omit best-effort entirely; it cannot silently fall back to it.

P12-B has **NO HARD DEPENDENCY**. Its partial epoch/quiescence protocol is **OPTIONAL_REUSE** only when its selected profile and complete projected owner set are proven; its current partial census is insufficient for FR-C coherence. P12-C/P12-A require **ARCHITECTURAL_ALIGNMENT** if they later reuse the same identity/read seams; no persistence DTO becomes a factual API. WI-A is **NO DEPENDENCY** for this generic foundation: capture identifies the runtime/boundary, and an identity-bearing export later combines the completed FR-C capture with the separately published WorldId. P18 is **ARCHITECTURAL_ALIGNMENT** for completed logical boundaries, not a redesign. P19 is **NO DEPENDENCY**.

## Implementation surface and validation

Expected files: new `FactualRead/*` contracts/coordinator and `.meta` files; a narrow `SimulationRuntime` admission/read facade and boundary witness; focused EditMode tests. Do not alter domain Stores to serve consumers or touch P12-B owner census code. Implementers must audit the actual selected writer paths and ensure the supported owner-thread contract holds before asserting `Coherent`; if that cannot be demonstrated, return `Unavailable` and bring a bounded revision of this design for review rather than weakening the label.

Tests: present versus authoritative absent, unsupported capability, unavailable during bootstrap/advance/fault/wrong thread, explicit outside-scope classification for display/Knowledge requests, known-empty collection, no mutable alias escaping, stable deterministic capture order, before/after revision or boundary change fails atomically, exception fails atomically, reentrant capture fails, best-effort cannot pass the coherent-export gate, and a headless serialized host can capture with the same contract. No P12-A/P12-B/full P12 completion or P19 is required.

**Completion:** a bounded, capability-oriented factual read protocol with honest status and coherency labels, without a giant export DTO or a false global snapshot claim.
